Review progress on a plan and re-plan honestly. Target plan: $ARGUMENTS

Apply the `planning-method` skill (Review and re-plan).

Steps — all mandatory, in order:

1. **Load the plan** from the working folder. Ask which one if ambiguous. If the person
   asked to review everything, scan every `plan-*.md` in the folder first and flag
   approaching target dates and stale last-reviewed dates before going plan by plan.

2. **Set every status.** Each milestone and action becomes done, in progress, not
   started, or blocked — updated in the plan file. Ask about anything unclear; never
   guess what got done. Split partially-done actions into a completed action and a
   remaining action.

3. **Diagnose every stuck item.** Assign the cause: no time, blocked on
   someone/something, or wrong scope.

4. **Re-plan.** Re-estimate, re-sequence, cut scope, or move the target date to match
   reality. State it plainly if the critical path changed. If existing reminders are
   now stale, update them — re-running the scheduling gate for every change.

5. **Update the plan file in place** — statuses, Schedule section, and a dated
   append-only Log entry describing what changed.

6. **End with the single next action.**

Privacy — mandatory: the plan stays in the working folder; de-identify before any
external call; halt and get confirmation before any step that would send sensitive
data off the machine.
